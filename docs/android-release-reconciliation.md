# Mandatory Android release reconciliation — desktop and laptop

This is a build prerequisite, not authorization to build. Local SDK/JDK/Gradle is the default. Cloud builds require the user's specific current request; no automatic fallback. Use one registered home and one writer per repo, with the actual session lease. Never make a separate source/build checkout, reset away work, force-push, uninstall, downgrade or change signing keys to resolve a conflict.

1. Preserve existing dirty work. Commit and push only scoped work. Run `npm run release:survey` to freshly fetch **all** GitHub heads/tags and list exact branch tips and ancestry. Inspect other-machine branches, commits and packets; branch dates alone do not establish relevance. WB-M's known laptop lane is `codex/wbm-stale-level-20261005`; WB-T's is `codex/wbt-enroute-20261014`. Discover new lanes too. Unpushed work on another computer cannot be discovered: explicitly report this limitation and never call GitHub fetch proof of complete laptop synchronization.
2. Identify the intended release branch and expected commits from both computers. Inspect `git log --left-right --cherry-pick RELEASE...origin/OTHER` and the full release delta (`git diff BASE..SOURCE`, not only this task's files). Reconcile relevant features by normal merge or deliberate reviewed cherry-picks with evidence; verify expected commit ancestry. If cherry-picked identity differs, record both hashes and demonstrate patch equivalence, then require the resulting commit in expectedCommits. Do not blindly merge historical/unrelated lanes. Explain each excluded branch in the manifest. Stop on conflicting ownership/state and preserve both sides. No automatic reconciliation is performed by the tool.
3. Audit versionCode **for this package** across published distribution, EAS/cloud history (read-only queries), GitHub release reservations and manifests on every relevant branch, local SDK manifests/APK metadata and uploaded artifacts from both computers, and user-reported/ADB-installed versions. Latest EAS is not latest local Gradle. Read APK package/version/certificate with aapt/apksigner; filenames alone are insufficient. Record evidence locations, UTC times and maximum for each category. Missing cloud/published/other-machine evidence is a blocker, not zero. If a category truly has no builds, document the checked authoritative source and use zero. User reports are evidence of a minimum, not independent device verification. Known floors as of2026-10-27: WB-M119 locally released; WB-T274 user-reported on ZFold/laptop checkpoint; WBE98 and WBS100 user reports belong to their separate package sequences. This does not authorize editing/building those other apps. Allocate strictly above all known values/reservations; retain package ID and signing SHA256 from `android-release-history.json`. Refresh all evidence within24h (and again if new movement/build is reported).
4. Update both app.json AND native Gradle package/version to the allocated value, preserve native hooks/plugins/profile environment and release signing. Run relevant checks on combined source, recording commands, exact source hash and logs. Push the final commit; verify clean tree and exact intended remote HEAD. Do not auto-commit unrelated files. Pre-existing untracked work blocks the strict build gate until deliberately preserved/reviewed outside the build input under workspace policy; never use git clean. Documentation changes alone do not require rebuilding.
5. Prepare a non-secret JSON release manifest outside the source tree using the schema below. `node scripts/release-preflight.cjs check MANIFEST.json` freshly fetches all GitHub heads/tags, verifies reviewed tips, expected ancestry, clean/pushed source, full-delta/check attestations, package/native version and audited version ceilings. Evidence is reviewed attestation: the tool cannot read an unplugged laptop or magically verify log contents. Do not include passwords, tokens, keystore files, environment dumps or service credentials.
6. Exactly ONE release owner/session controls allocation through completion across computers; a local workspace lease is not a cross-computer lock. `node scripts/release-preflight.cjs reserve MANIFEST.json` publishes immutable annotated Git tag `android-release-vN` pointing at the exact source, with the manifest as annotation. Normal GitHub tag creation is the atomic reservation: competing same-version pushes fail. Never force-update/delete reservations, including failed builds. Verify remote reservation owner/source/content before build. Different-number simultaneous releases remain prohibited by the single-owner rule; no server-wide exclusive lock exists.
7. Immediately before local build, use `node scripts/release-preflight.cjs build MANIFEST.json -- :app:assembleRelease -PreactNativeArchitectures=arm64-v8a --max-workers=2 --no-daemon`. It verifies the remote reservation and freshly fetches/rechecks ALL branch tips; any movement requires renewed reconciliation/delta review/checks/manifest and an unused reservation. It forces JS bundle regeneration first (Gradle can cache locale JSON incorrectly), then assembles in the existing registered android directory. No source copy, cloud build or upload is launched. Use existing SDK/JDK/signing environment. Follow WB-T's existing build-info generation policy deliberately: its generated utils/buildInfo.ts is TRACKED despite old generator comments. Do not silently dirty/restore it or falsely claim a clean build; resolve metadata generation and record exact generated input before the next release. Build mode intentionally refuses tracked source mutation.
8. Verify final APK metadata, approved signing fingerprint, SHA256, expected embedded features/strings and source provenance before upload. Preserve unique APK filenames and prior builds. Complete a durable **GitHub** provenance record in `docs/android-release-history.json`: source commit, package, versionCode/versionName, signing SHA256, APK SHA256, local SDK/Gradle/profile, build time, checks, relevant branch reconciliation, artifact/Drive object and verification state. Commit/push that evidence-only follow-up without claiming the APK includes that later docs commit. Reservation annotation remains immutable source-time evidence. Recheck remote movement after building; if relevant source moved, do not claim current synchronization or silently publish obsolete source. User-installed state requires actual device evidence, separately from build/upload.

## Manifest schema

JSON fields (actual values required; not an executable assignment):

- `schemaVersion`:1; `owner`:{`session`,`machine`}; `sourceCommit`:full40hex; `releaseBranch`:exact branch; `packageId`; `versionCode`; `signingCertificateSha256`.
- `unpushedWorkLimitation`:exact text `Other-machine unpushed work cannot be discovered`.
- `reviewedBranches`:map of **every** current GitHub head to {`commit`:fullhash, `disposition`:`included` or `excluded`, `reason`:exclusion rationale}. Included heads must be ancestors. Branch exclusions must be genuinely reviewed, never auto-populated as irrelevant.
- `expectedCommits`:nonempty list of full hashes from both machine histories required in source ancestry.
- `deltaReview`:{`base`:last applicable release source, `sourceCommit`, `evidence`:full diff review record}.
- `checks`:[{`sourceCommit`,`command`,`result`:`passed`,`evidence`:log location}]. Baseline failures need explicit review/disposition and passing relevant checks; do not label failed checks passed.
- `versionAudit`:each of `published`,`cloud`,`localManifests`,`localArtifacts`,`installed` has {`maxVersionCode`:integer, `checkedAt`:UTC timestamp, `evidence`:specific authoritative report/log/source}. Include remote reservation floors; the gate also queries reservation tags.

Run focused gate regression checks with `npm run release:gate:test`. WB-T's `node tools/test-releasePreflight.mjs --manifest MANIFEST.json` retains native/outbox checks and runs the full reconciliation gate. Static native checks alone are never build clearance.
